⚙️ Flyway Migrations — application_db

V1__Create_job_applications_table.sql
Creates job_applications table with all base columns, indexes on user_id/job_id/recruiter_id/status/applied_at, and UNIQUE(user_id, job_id) constraint to prevent duplicate applications.
V2__Add_uuid_to_job_applications.sql
Adds uuid CHAR(36) column, backfills existing rows with UUID() values, makes it NOT NULL, and creates UNIQUE index — needed to expose public-safe IDs to the API without exposing auto-increment integers.
V3__Phase_improvements.sql
Makes resume_url NOT NULL (backfills legacy rows with placeholder), enforcing that every application must have a resume. Aligns constraint with Phase 1 business requirement.

💡 INTERVIEW TALKING POINTS — Database Design

  • Database-per-service pattern: "Each service owns its schema — auth_db, job_db, application_db, notification_db. There are NO cross-service JOINs. This is the database-per-service pattern from microservices architecture."
  • No foreign key constraints across services: "job_applications.user_id references users.id logically, but there is no DB foreign key constraint. This is intentional — cross-service referential integrity is maintained at the application layer via Feign validation."
  • UUID vs BIGINT: "Every table has both an auto-increment BIGINT primary key for fast joins within the service, AND a UUID exposed externally via the API. This avoids leaking row count/sequence information and allows safe public URLs."
  • Denormalization in job_applications: "job_title and company_name are denormalized into job_applications. If a recruiter edits the job later, the application still shows the snapshot of what was posted when the user applied."
  • Idempotency table: "processed_kafka_events stores topic:partition:offset as a unique key. If Kafka redelivers a message, the second insert throws a unique constraint violation, which we catch to skip duplicate email sending."
  • Flyway vs auto-create: "application-service uses Flyway for production-grade versioned migrations. Other services use JPA hbm2ddl=update. In a real production environment, all services would use Flyway."
