Why Microservices?
Each service is independently deployable and owns its data. auth-service owns auth_db, job-service owns job_db, etc. Services communicate via Feign HTTP clients (synchronous) or Kafka topics (async). A failure in notification-service does NOT bring down job postings.
⚡
Why Kafka?
When a user applies for a job, application-service publishes an ApplicationEvent(action=SUBMITTED) to Kafka. The notification-service consumes it and sends confirmation emails — without coupling the two services. Kafka also ensures at-least-once delivery with idempotency keys stored in processed_kafka_events table.
🛡️
Why a Single API Gateway?
The gateway is the single entry point for all client traffic. It validates JWT once (JwtAuthFilter), strips the token, and injects X-User-Id, X-User-Email, X-User-Role headers. Downstream services never re-validate JWT — they trust the gateway-injected headers. CORS, rate limiting, and Swagger aggregation all live in one place.
💾
Why Redis?
Redis stores OTP codes with TTL (auto-expire) — no DB cleanup job needed. It also caches job listings and statistics in job-service to avoid expensive DB queries on every search. Cache is invalidated on job create/update/delete via Spring's @CacheEvict.
📡
Server-Sent Events (SSE)
The React Navbar subscribes to /api/v1/notifications/my/stream?token=JWT. Since browsers cannot send custom headers with EventSource, the JWT is passed as a query parameter. The gateway's JwtAuthFilter handles this special path and injects X-User-Id normally. The connection is a long-lived HTTP stream — no polling needed.
🔄
Admin Service — No Own Database
admin-service is a pure aggregator. It has no MySQL database. Instead it uses Spring Cloud OpenFeign to call auth-service, job-service, and application-service. Each Feign client has a Resilience4j circuit breaker that returns empty/zero data if downstream fails — dashboard stays up even if one service is down.

💡 INTERVIEW TALKING POINTS — Architecture

  • Service boundary decision: "I chose to separate file-service so that Cloudinary credentials are isolated — no other service needs cloud storage configuration."
  • Database-per-service: "Each service owns its schema. application-service uses Flyway for versioned migrations (V1–V3). Other services rely on JPA's hbm2ddl auto-create."
  • Token refresh: "Axios interceptors silently refresh the access token on 401 — the user never sees a forced logout unless the refresh token itself expires."
  • Idempotency: "Kafka consumers check the processed_kafka_events table before acting on any event. This prevents duplicate emails if Kafka redelivers a message."
  • Circuit breakers: "Resilience4j wraps every Feign call in admin-service. If auth-service is slow, the circuit opens and admin returns cached/empty data instead of cascading failure."
  • SSE vs WebSocket: "I chose SSE because notifications are server-to-client only. SSE is simpler (HTTP), firewall-friendly, and auto-reconnects. WebSocket would be overkill here."
